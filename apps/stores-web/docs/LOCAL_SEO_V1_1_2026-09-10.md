# Local SEO V1.1 — safe internal-linking layer

Date: 2026-09-10
Scope: `apps/stores-web` only.

## Goal

Strengthen Amursk local-intent relevance without adding a catalog, duplicating CMS content, or inventing commercial facts.

## Verified facts used

- City: Амурск, Хабаровский край, Россия.
- Address: проспект Победы, 16.
- Four published brand directions: «Ампер», «Вентиль», «Метиз Маркет», «Миска».
- Existing brand short descriptions, store records and bonus information are reused from the current content layer.

## What changed

1. `/stores/{city}/` now links each active brand present in that city to its brand landing page and displays the existing verified short description.
2. `/stores/{city}/{store}/` now links back to the corresponding brand landing page.
3. `/faq/` now has a compact «Полезные разделы» block linking to contacts, stores and the bonus program.
4. Existing city JSON-LD from the SEO audit is preserved.
5. Regression tests cover unique static metadata and the new internal-linking contracts.

## Deliberately excluded

No new FAQ records were added to mock data or Directus. Production reads Directus, so adding FAQ content only to mock/seed would create a false local-only feature and would require a CMS write to become visible.

No changes were made to:
- Directus schema, seed logic or production data;
- GitHub Actions workflows;
- promotions, vacancy state, prices, stock or assortment claims;
- routes, sitemap structure or e-commerce functionality.

Future category landing pages should be added only when their content can be backed by verified commercial facts and a clear search-intent need. Avoid doorway pages and keyword stuffing.

## Validation

Required before merge: `npm test`, `npm run lint`, `npm run typecheck`, hermetic `npm run build`, `git diff --check`, and secret scan. After deploy, run the existing production smoke and SEO audit.
