# Confirmed payment cart cleanup — 14 October 2026

Only a successful, no-store `/api/payments/ozon/status` response with `state: paid`, the requested order ID and a valid product total triggers cleanup and purchase analytics. Submission, the Ozon redirect, pending, cancellation and failure do not authorize cleanup. The success page waits beyond one minute with a 30-second backoff and retries on focus/visibility changes.

Before any asynchronous checkout work, the browser stores SKU/quantity eligibility in `vozdooh-cart-v1`. After submission it binds the snapshot to the returned order ID. No contact, price or payment credentials are stored there. Quantity reductions consume original eligibility first; increases never add eligibility. Removing or clearing products then adding them again preserves those new units. Cleanup compares the confirmed IDs and quantities with the original snapshot, removes only remaining eligible quantities, and persists the cart and cleanup receipt in one localStorage write. Existing cart subscriptions update the badge in the current document and other tabs. Web Locks serialize paid callbacks across supported browser tabs.

Analytics receipts are independent of cleanup. Existing tracked receipts do not skip status verification or cleanup. LocalStorage, sessionStorage and document memory prevent repeated purchase events. When all persistent browser storage is unavailable, deduplication cannot survive a new document or browser restart; cleanup remains conservative and retries failed writes. Orders created before this release, another browser, missing/corrupt snapshots or arbitrary cart replacement lack safe provenance and retain their cart rather than deleting newer items. Products added by an older open application tab can erase metadata; that also preserves the cart conservatively.

No server payment, product, price, delivery, pickup, mail, indexing or worker behavior changes. Production still charges only products through Ozon Pay; delivery charges are agreed separately. Free pickup remains at the approved fixed address, after readiness confirmation.

Validation passed: `npm run verify` (165 Node tests, 2 integration tests, 9 Python tests, TypeScript, ESLint and Next build). Candidate browser verification passed all 16 payment/cart scenarios and 6 delivery/checkout scenarios at 390px and 1280px. Opt-in mocked browser tests: `scripts/verify-paid-cart-browser.cjs` and `scripts/verify-pickup-browser.cjs`, using `VOZDOOH_QA_URL`, `VOZDOOH_QA_SKU`, `PLAYWRIGHT_MODULE`, `CHROMIUM_PATH` and optional `VOZDOOH_QA_PROXY`. The tests intercept every write and payment status; they create no real orders, charges or emails. Desktop and mobile cover delayed confirmation beyond the former limit, cart edits in another tab, repeated returns, pending/canceled/failed states and storage failures.

Deployment uses only `/opt/vozdooh/runtime/compose.yml` and replaces the web image. Backup and rollback: `/opt/vozdooh/backups/deploy/paid-cart-20261014/rollback.sh`. The worker is preserved. Rollback restores the previous web image and compose without changing persisted orders or mail. New metadata is additive; the previous browser cart reader ignores it.
