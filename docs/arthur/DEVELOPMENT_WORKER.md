# Arthur Development Worker — этап 1

Цель: единый безопасный исполнитель технической диагностики проектов Артура
без shell/SQL от LLM и без доступа к токенам, чекам, клиентским данным и 1С.

## Реализовано

`node scripts/arthur/development-worker.js check all`

Регистр проектов — `scripts/arthur/dev-worker/projects.js`. Он жёстко
ограничивает допустимые сайты и Docker-контейнеры; произвольные URL и команды
запрещены. В v1 нет операций deploy, exec, write и изменений production.

- amurskmarket.ru: главная, /api/health, robots.txt, sitemap.xml
- vozdooh27.ru: главная, robots.txt, sitemap.xml
- Windows Amursk: состояние бизнес-KPI, закупщика и Arthur Gateway через
  Docker inspect без shell/редактирования контейнеров.

Результаты: healthy/degraded/not_checked для проекта; healthy/partial/
degraded для общего статуса. На VPS проверки Windows отмечаются
not_checked, а не здоровыми. HTTP 200 не доказывает работоспособность
бизнес-операций или индексации.

`node scripts/arthur/dev-worker/monitor_runner.js` сохраняет
только безопасные статусы, длительности и категории ошибок, без ответов,
токенов и клиентских данных. Максимум 192 собственных файла; посторонние
файлы не затрагиваются. Фоновый запуск требует отдельной проверки
учётной записи и защищённых Windows ACL.

## Границы полномочий

Read-only диагностика не изменяет код, 1С, KPI, цены, бонусы,
платёжные настройки, заказы, каталоги или сайты.

Следующие этапы:
1. Проверенные расписания мониторинга и логирование результатов.
2. Read-only Development Skill в Arthur с безопасным статусным API.
3. Каталог сервисов с командами тестов и ответственными окружениями.
4. Изолированные сборки и release-candidate, CI и rollback.
5. Одобрение владельца для записей в 1С, ценах, платежах и заказах;
   аудит с durable idempotency key.
6. Реальный E2E Telegram и подтверждённые уведомления при сбоях.

Тест: `node --test tests/dev-worker/*.test.js`.

Рабочие сервисы и сайт **не обновляются** этим исполнителем.
