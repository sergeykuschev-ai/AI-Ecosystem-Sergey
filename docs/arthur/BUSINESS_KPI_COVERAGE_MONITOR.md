# Arthur — read-only контроль качества данных бизнес-портала

Состояние 09.10.2026. Эта задача **не формирует KPI заново** и не
исправляет ошибки в данных. Она считывает существующий авторизованный
Business KPI API и публикует только агрегированное состояние.

## Запуск на Windows Amursk

- Планировщик: `Arthur-Business-KPI-Coverage`, SYSTEM, повтор каждые 3 часа
- Script: `C:\AI-Ecosystem\candidates\arthur-kpi-coverage-20261009\arthur-kpi-coverage-host-runner.cjs`
- Права отчётов: защищённый Windows ACL SYSTEM/Administrators
- Отчёты: `C:\AI-Ecosystem\local-services\arthur-kpi-coverage-reports\status.json`
  и append-only `kpi-*.json` (до 96)
- Работает **вне** production процесса Gateway: host Node отправляет
  read-only JS скрипт по STDIN уже работающему
  `arthur-core-telegram-gateway-1`; внутри используется существующая
  service-авторизация Business KPI. Ни один ключ не возвращается,
  не сохраняется в отчёте и не появляется в коде.

## Что собирается

Для всех зарегистрированных в KPI API магазинов:
- `COMPLETE`, `PARTIAL`, `NO_DATA` или `UNAVAILABLE`;
- число смен текущего месяца, число сегодняшних смен;
- признаки наличия выручки и доли QR, **не денежные суммы**;
- число записей журнала импортов;
- время проверки и период (Asia/Vladivostok).

Ни имён сотрудников, ни телефонов, ни секретов, ни размеров выручки.

### Первый реальный результат

| Магазин | Статус | Смены октября | Импортов |
| --- | --- | ---: | ---: |
| Миска | COMPLETE | 9 | 4 |
| Ампер | PARTIAL | 9 | 0 |
| Вентиль | PARTIAL | 9 | 0 |
| Метиз Маркет | NO_DATA | 0 | 0 |

По Амперу и Вентилю сегодня есть по одной смене через KPI API, поэтому
отсутствие записей в журнале импортов само по себе не доказывает
отсутствия загрузки данных и тем более отсутствие продаж. Источник
и покрытие требуют отдельного аудита.

## Подтверждённая проверка

- Unit tests: **4/4 PASS** (VPS и Windows);
- Первый read-only API run на Windows: **4/4 магазинов обработаны**,
  итоги 1 COMPLETE, 2 PARTIAL, 1 NO_DATA;
- Scheduled Task запущена вручную под SYSTEM, код `0`, выходной отчёт
  подтвердил те же значения;
- Текущий Arthur Telegram Gateway после проверок: **healthy**.

## Что запрещено и не проверено

- Запрещены любые POST/PUT/PATCH/DELETE, перепроведение смен, изменение
  товаров, заказов, продавцов или данных 1С;
- Не отправляются автоматические Telegram-тревоги по `PARTIAL`:
  это показатель полноты данных, а не технический отказ сайта;
- Не утверждать, что report COMPLETE удостоверяет реальную
  достоверность суммы выручки без сверки с первичными документами.

Рекомендации: аудит источника данных Метиз Маркет, затем причины PARTIAL
для Ампера и Вентиля, затем сверка эквайринга и выручки с 1С при
доступной интеграции.
