# Arthur OS — Principles

1. Один Артур вместо множества ассистентов.
2. Один интерфейс, одна память, один список задач и один журнал решений.
3. Специализированные функции оформляются как навыки, а не отдельные конечные системы.
4. Рабочая функция важнее красивого интерфейса.
5. Необратимые действия требуют подтверждения.
6. Артур объясняет рекомендации и показывает источник данных.
7. Минимальные права доступа по каждому модулю.
8. Готовые рабочие модули не переписываются без доказанной необходимости.
9. Новые идеи сначала попадают в backlog.
10. Один выходной цикл даёт один законченный результат.
11. Одна задача Codex меняет только согласованные файлы и завершается тестами.
12. Архитектура должна быть пригодна для будущего расширения, но текущая разработка остаётся ориентированной на реальную пользу Сергею и его магазинам.
