**Дата:** 2026-07-29  
**Статус:** каноническая карта этапа 0

## 1. Подтверждено в репозитории

### AI-закупщик «Миска» — зрелый рабочий модуль

Расположение и точки входа:

- `agents/purchasing/` — расчётное ядро и тесты;
- `apps/purchasing-web-backend/` — локальный backend и owner-facing web-интерфейс;
- `scripts/run-purchasing-agent.js` — полный запуск;
- `scripts/diagnose-purchasing-workbook.js` — диагностика выгрузок;
- `scripts/compare-purchasing-workbooks.js` — сравнение выгрузок;
- `scripts/build-purchasing-matrix.js` — Matrix Builder;
- `data/purchasing/` — конфигурации, матрицы и рабочие данные;
- `docs/purchasing-*.md` — действующая документация.

Доступные npm-команды:

- `npm test`;
- `npm run purchasing:run`;
- `npm run purchasing:diagnostics`;
- `npm run purchasing:compare`;
- `npm run purchasing:matrix:build`;
- `npm run purchasing:web`;
- `npm run finance:update:miska`;
- `npm run finance:check:miska`.

Подтверждённые функции:

- анализ Excel-выгрузок SmartZapas/Min-Max;
- обязательная ассортиментная матрица;
- финансовый контроль;
- объяснение рекомендаций;
- Owner Review и история решений;
- Learning Center;
- кандидаты правил, materialization и ручное управление статусами;
- Rule Effectiveness и Knowledge Health;
- локальный web-интерфейс;
- защита от автоматического изменения заказа и правил.

**Решение:** не переписывать. Подключить к Arthur Core как навык через стабильный адаптер.

## 2. Подтверждено вне репозитория

Следующие активы существуют в рабочей инфраструктуре, но пока не представлены в репозитории как переносимые конфигурации:

### Сервер и контейнеры

- Docker Desktop на рабочем сервере;
- контейнер n8n;
- контейнер Open WebUI;
- Ollama;
- отдельный немецкий сервер Ubuntu;
- удалённый доступ к рабочей инфраструктуре.

**Статус:** работает, но конфигурация не инвентаризирована в коде.

**Нужно:** безопасно сохранить обезличенные `docker compose`/описания контейнеров, список volumes, сетей, backup-процедуры и переменные окружения без секретов.

### База знаний «Миски»

Существует подготовленная база знаний по:

- магазину и стандартам работы;
- ассортименту и брендам;
- заказам и Min/Max;
- правилам продавцов и консультациям.

**Статус:** содержимое находится в других чатах/файлах и ещё не импортировано в репозиторий.

**Целевой модуль:** `Академия Миски` и общий knowledge layer Arthur OS.

### Google Формы и тесты сотрудников

Начата система тестирования сотрудников через Google Формы.

**Статус:** внешний временный интерфейс; точная форма, вопросы, ответы и таблица результатов пока не зафиксированы в репозитории.

**Решение:** не развивать Google Формы как отдельную платформу. Сначала экспортировать вопросы и структуру, затем использовать их в Академии Миски.

### KPI продавцов

Существуют рабочие таблицы и правила анализа:

- выручка;
- средний чек;
- товары в чеке;
- допродажи;
- лакомства;
- выполнение плана;
- разделение причин: качество работы продавца или недостаточный трафик;
- динамика по сотрудникам.

**Статус:** используется операционно, но не подключено к единому хранилищу Arthur OS.

### Ревизии

Есть выполненный анализ сличительной ведомости и требования к будущему модулю:

- поиск пересортов;
- крупные недостачи;
- разделение ответственности;
- история ревизий.

**Статус:** концепция и реальные примеры существуют вне репозитория.

## 3. Не найдено как готовый модуль

На текущем этапе не считаются реализованными:

- Arthur Core;
- единая PostgreSQL-память;
- единый task manager;
- Telegram Gateway Артура;
- Gmail-контур;
- Calendar-контур;
- Instagram-модуль;
- Академия Миски;
- KPI-модуль;
- модуль ревизий;
- travel/booking-модуль;
- сайт и клиентский AI-консультант.

Наличие идей, документов или ручных процессов не означает готовность программного модуля.

После этапа 0 не начинаем весь Arthur Core сразу.

1. спецификация `Arthur Core v0`;
2. минимальная структура данных для профиля, задач, решений и подтверждений;
3. контракт навыка, через который позже подключится закупщик;

5. без изменений существующего purchasing pipeline.
