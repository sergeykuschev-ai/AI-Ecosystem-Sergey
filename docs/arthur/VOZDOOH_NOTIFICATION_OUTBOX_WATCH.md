# VOZDOOH: контроль очереди уведомлений (09.10.2026)

Этот монитор **не отправляет** сообщения в Telegram и **не меняет** заказы,
платежи, сведения покупателей или очередь уведомлений.

## Где работает

Источник заказов VOZDOOH сейчас находится на `stores-web1` в Docker
`vozdooh-commerce-worker`. В отличие от бизнес-портала и Артура (Windows
Amursk), наблюдатель расположен рядом с уже работающим commerce worker.

- Код наблюдателя: `/opt/stores-web/monitoring/arthur-vozdooh-notifications/observer.cjs`
- Обёртка: `.../run.sh`
- Текущее состояние: `.../status.json`
- История: `.../reports/outbox-*.json`, удаление записей старше 14 дней
- Расписание: `/etc/cron.d/arthur-vozdooh-notification-audit`,
  **каждый час в 30 минут**, cron active
- Права: observer и текущий отчёт `600`, run.sh `700`,
  cron файл `644`, владелец root

Обёртка запускает read-only код через `docker exec -i ... node -` —
никаких изменений образа, файла заказа, PostgreSQL или `1С`.

## Какие данные отчёт содержит

Только обезличенные счётчики:
- число сохранённых заказов по состояниям оплаты;
- число `PAID`, попавших в период включения уведомлений;
- число `PAID`, у которых через 10 минут нет события
  `payment_confirmed` в outbox;
- по очереди `pending/retry/sent/skipped`, количество записей,
  просроченных более чем на 15 минут;
- повреждённые файлы/ошибки конфигурации;
- `upstreamAckRecorded` — в очереди есть `sent`. **Не гарантирует,
  что владелец увидел сообщение в Telegram.**

Идентификаторы заказов, контакты покупателей, содержимое заказов и
подписывающие секреты в статус не попадают. Старые `PAID`, оформленные
до порога уведомлений, не ставятся в очередь повторно.

## Проверка при выпуске

- Node unit tests **3/3 PASS**: пустая очередь, пропущенное уведомление
  после оплаты, просроченный retry, отсутствуют ПД в output.
- Контрольный запуск на настоящих данных: 5 заказов, 1 `PAID`
  до начала периода уведомлений, `eligiblePaid=0`,
  `pending/retry/sent=0`, `missing=0`, `state=ok`.
- Настоящих подтверждённых успешных отправок пока нет
  (`upstreamAckRecorded=false`).
- Cron system service active; выполнено два ручных тестовых запуска
  wrapper с code 0.

## Что пока НЕ готово

- Автоматическая отправка *телеграм-алерта* при проблемах в outbox —
  отсутствует до безопасного включения подписанных inbound обработчиков.
- Подписанный VOZDOOH receiver в Arthur Windows ещё не активирован:
  см. issue #246 и PR #245. Его HMAC секрет нельзя публиковать или
  переносить через заблокированный удалённый канал.
- Реальный event E2E после новой оплаченной покупки не проверен.
- Это наблюдение за уведомлениями, а не подтверждение оплаты/передачи
  Ozon/полноты 1С.

Для отключения без влияния на бизнес-процессы:
`rm /etc/cron.d/arthur-vozdooh-notification-audit`.
