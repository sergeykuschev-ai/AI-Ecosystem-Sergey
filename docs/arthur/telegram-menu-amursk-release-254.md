# Артур: безопасный выпуск Telegram-меню (#254, draft PR #255)

Дата проверки: 2026-10-10. Целевой сервер: **Амурск**.

## Подтверждённые исходные состояния

Рабочий контейнер: `arthur-core-telegram-gateway-1`, образ `arthur-telegram-gateway:codex-notify-stage-20261010` — healthy при проверке. Исходный `/opt/arthur/agents/arthur-v1/telegram/telegram_gateway.js` имеет SHA-256:

`be9cfe6f8adf4ea9c1f00e7baea6ab0757471574dcbf7af2a0aa44cef680f049`.

Живой файл содержит `handleReminderCallback(callback)`, `ar1:` (завершить/отложить/отменить), голосовые сообщения, повторяющиеся задачи и другие компоненты. **Не заменять его файлом из GitHub `main` или PR #255 целиком.** У GitHub `main` на момент проверки старый Gateway без этого обработчика. Существующий staged Harness-кандидат тоже имеет другой hash; не считать его копией live.

PR #255 предлагает отдельный owner-only контроллер `owner_menu.js` и тесты, но это пока лишь исходный код. В живом Telegram новое меню не активировано.

## Точное правило интеграции (только после разрешённого code review)

1. Сначала сделать рабочий резервный образ/backup **реального** Gateway и доказать способность вернуться к нему. Зафиксировать digest, git SHA, переменные окружения без значений секретов.
2. Перенести только `owner_menu.js` и необходимые совместимые обработчики в актуальный live-derived код, сохранив его импортированные навыки, память, голос, повторения, расписания, подсистему закупщика, API и колбэки напоминаний.
3. В `handleUpdate(update)` обрабатывать **строго `am1:` только при `ARTHUR_TELEGRAM_MENU_ENABLED=1`**, перед существующим ветвлением для `ar1:`; иначе передать update в уже работающий `handleReminderCallback()`. Никогда не передавать старые `ar1:` в новое меню.
4. Текст `/menu` и подписи кнопок распознавать только в доверенном личном Telegram-чате владельца (совпадение `from.id` и `chat.id`); любые другие тексты и голос оставить прежним роутам. Пользовательская кнопка «Задачи» вызывает существующий запрос по задачам, а «Статус» — штатную диагностику. «Согласования» пока информационны, не меняют состояние задач, «Разработка» ведёт в GitHub/ChatGPT, **не вызывает Windows Codex worker**.
5. `sendMessage` с клавиатурой должен передавать `reply_markup` без изменения обычной отправки сообщений. На `am1:` callback отвечать `answerCallbackQuery` с явным перехватом ошибок; не перехватывать старые callback ID.
6. **По умолчанию OFF**: если `ARTHUR_TELEGRAM_MENU_ENABLED` не равно `1`, не создавать меню и не менять старое поведение.

## Release gate

Два разных аспекта:
- GitHub CI на PR №255 может быть зелёным для репозитория; это **не** доказывает совместимость с живым Gateway на сервере.
- `agents/arthur-v1/telegram/owner_menu_release_gate.js` — дополнительная read-only проверка: обязательны наличие старого `ar1:`, новой owner-only маршрутизации, прохождение регрессий, реальный canary владельца и проверенный rollback.

Порядок допусков:
1. Проверка code diff относительно **live source** (и минимальный размер патча).
2. Изолированные тесты: `ar1` старые/устаревшие/повторно нажатые; `am1` новые; посторонний пользователь/группа; `/menu`, произвольный текст, голос, расписания; время ответа/сеть/ошибка Telegram.
3. Тестовый образ **без перезапуска рабочего Gateway**, сначала `ARTHUR_TELEGRAM_MENU_ENABLED=0`.
4. Проверенный откат **к прежнему образу и настройкам**, если кнопки ведут себя неправильно.
5. Только после успеха — согласованный canary в личном Telegram владельца и явное разрешение на включение.

## Важное ограничение

Попытка дополнительного чтения live Gateway в этом сеансе **заблокирована системой безопасности**. Не использовать альтернативные средства для обхода этого запрета. Дальнейшее применение патча к рабочему Gateway и запуск его тестов зависят от разрешённого метода обновления. Не утверждать, что меню уже появилось в Telegram.
