# VOZDOOH: основной код магазина и автоматизация разработки

Дата: 23 октября 2026. Основная цель: [GitHub #262](https://github.com/sergeykuschev-ai/AI-Ecosystem-Sergey/issues/262).

## Зачем нужны две папки

В GitHub `main` до этого изменения уже находилось `apps/vozdooh-web` — ранний прототип брендовых страниц (29 файлов); в нём нет всего действующего магазина с оплатой, каталогом, 1С и доставкой.

На рабочем сервере VOZDOOH в production используется иная, более полная линия разработки. Чтобы не перезаписать существующий прототип, исходники продакшена добавлены **рядом**:

| Путь в `main` | Назначение |
| --- | --- |
| `apps/vozdooh-web/` | Сохранённый прежний прототип. Его не удаляем и не используем для релиза работающего магазина. |
| `apps/vozdooh-commerce/` | **Основная линия интернет-магазина** с корзиной, 1С, заказами, Ozon, карточками и SEO. |

Названия папок разграничивают две несовместимые кодовые базы. Во время будущего выпуска следует явно указывать build context новой папки и отдельно сверять runtime-настройки, а не полагаться на старое имя `apps/vozdooh-web`.

## Проверки изменений

Для `apps/vozdooh-commerce` использовать `npm ci`, `npm test`, `npm run typecheck`, `npm run lint` на отдельной ветке. Первая подготовленная версия прошла **238/238** Node-тестов, TypeScript и ESLint без ошибок, согласно логам `/opt/vozdooh/candidates/seo-product-variants-20261023/`.

GitHub branch/commit не становится автоматически «выпущенной версией». Без новых прав `workflow` для GitHub-токена нельзя загрузить новый GitHub Actions workflow. До разрешения этого вопроса проверять результаты локально и прикреплять к SHA коммита отдельно (не выдавать их за GitHub Actions).

В новых PR применять фильтр `apps/vozdooh-commerce/**`; не использовать `apps/vozdooh-web/**` для запросов по действующему магазину.

## Рабочая система автономного развития

1. **Сбор данных:** существующий `stores-web1` монитор, Метрика, Вебмастер при восстановлении доступности, каталог и остатки (1С без модификаций).
2. **Артур / triage:** выбирает только проблемы с проверяемыми фактами; создаёт GitHub Issue с маркером исключения дублей и привязкой к #262.
3. **Codex:** получает ограниченную задачу, работает в отдельной ветке `apps/vozdooh-commerce`, готовит draft PR. GLM — дополнительный review по необходимости.
4. **GitHub / тесты:** документированные QA и regression tests, проверка безопасности исходников и воспроизводимости. Сбой останавливает публикацию, а не мониторинг.
5. **Согласование:** Артур сообщает результат в Telegram; production release требует отдельного разрешения владельца, проверенного отката и подтверждённой версии.
6. **Оценка результата:** после выпуска — HTML/структурированные данные и измерение органики/покупок через 7/14/28 дней. Нет данных — нет заявления об улучшении.

Первый пилот: различить H1 и `Product.name` для промывочной жидкости AROMAgroup 110/150 мл, не меняя SKU, 1С, цены и остатки.

## Разрешённые и запрещённые операции

- Разрешены без отдельного production approval: read-only сбор, проверка данных, дедуплицированные Issues, изолированные ветки и draft PR, тесты.
- Не разрешены: автоматический merge, изменение цены/остатка, создание фиктивных оплат, вмешательство в заказы, перенос секретов в GitHub, запуск самописного кода с доступом к токенам.
- Без специальной технической проверки не удалять `apps/vozdooh-web` и не совмещать содержимое двух папок в одной директории.
- Для отключения ежедневного триажа на сервере: `sudo systemctl disable --now vozdooh-growth-triage.timer` (не отключает сам магазин).
